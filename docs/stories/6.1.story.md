## 6.1: Integrazione dell'upload di immagini nel form dei post del blog

**As an** administrator creating or editing a blog post,
**I want** to be able to upload a cover image directly from the form,
**So that** I don't have to manually host the image elsewhere and paste a URL.

### Acceptance Criteria

1.  The "Create/Edit Post" form (`PostForm.tsx`) must include a new file input field for uploading a cover image.
2.  The user must be able to select an image file (e.g., JPG, PNG) from their local machine.
3.  Upon file selection, the image should be uploaded to a dedicated bucket in Supabase Storage via a secure API endpoint.
4.  The API endpoint must ensure the user is an authenticated administrator.
5.  The API endpoint should rename the file to prevent name collisions (e.g., using a timestamp or UUID).
6.  After a successful upload, the API endpoint must return the public URL of the uploaded image.
7.  The frontend form should display a preview of the uploaded image and store the returned URL in its state.
8.  When the post is saved (created or updated), this image URL must be saved in the `imageUrl` field of the corresponding post in the database.

    *   Create a new reusable `ImageUpload.tsx` component in `src/components/admin` might be beneficial.
    *   Create a new API route at `pages/api/admin/upload.ts`.
    *   [Source: Standard Next.js project structure.]

*   **Component Specifications**:
    *   **`ImageUpload` (`src/components/admin/ImageUpload.tsx`):** A component that encapsulates the file input, upload logic (calling the API), and preview display. It could have a prop like `onUploadComplete: (url: string) => void`.
    *   **`PostForm` (`src/components/admin/PostForm.tsx`):** Will be modified to include the `ImageUpload` component and manage the `imageUrl` state.

*   **API Specifications**:
    *   **Endpoint:** `POST /api/admin/upload`
    *   **Request:** `multipart/form-data` containing the image file.
    *   **Response:**
        *   `200 OK` with a JSON body containing the public URL of the uploaded file: `{ "url": "https://<project>.supabase.co/storage/v1/object/public/<bucket>/<filename>" }`.
        *   `400 Bad Request` if the file is missing or of an unsupported type.
        *   `401 Unauthorized` if the user is not an authenticated admin.
        *   `500 Internal Server Error` on unexpected upload errors.
    *   [Source: `docs/architettura/6-vista-logica-componenti-e-relazioni.md` shows the API route to Supabase Storage flow.]

*   **Security & Storage**:
    *   The API route MUST be protected using the same authentication strategy as other admin APIs.
    *   The file should be uploaded to a specific bucket in Supabase Storage (e.g., `post-images`). This bucket should be configured with appropriate access policies.
    *   To mitigate the risk of "disordine" (disorder), the backend should generate a unique, consistent name for each uploaded file.
    *   [Source: `docs/architettura/5-rischi-architetturali-e-mitigazioni.md`]

*   **Testing Requirements**:
    *   Unit tests for the `ImageUpload` component.
    *   Integration tests for the `/api/admin/upload` endpoint (authentication, file handling, Supabase interaction).
    *   End-to-end tests for creating a post with an uploaded image.

### Tasks / Subtasks

1.  **(Setup)** Configure a new bucket in Supabase Storage (e.g., `post-images`) with public read access.
2.  **(AC: 1, 2, 7)** Create or modify the `PostForm.tsx` to include a file input and image preview area.

    *   Parse the `multipart/form-data` request.

    *   Upload the file to Supabase Storage.
    *   Return the public URL.
