## 5.3: Gestione (CRUD) delle Comunità

**As an** administrator,
**I want** to be able to create, read, update, and delete community entries through a dedicated interface in the admin panel,
**So that** I can manage the information about the communities efficiently and keep the public portal updated.

### Acceptance Criteria

1.  A new protected page must be created at `/admin/communities` to list all community entries.
2.  From the `/admin/communities` page, the administrator must be able to:
    *   View a list of all communities with their name, a short description, and an image.
    *   Navigate to a "Create New Community" page.
    *   Navigate to an "Edit Community" page for an existing community.
    *   Delete an existing community.
3.  A "Create New Community" page (`/admin/communities/create`) must allow the administrator to:
    *   Enter a name, slug, description, and image URL.
    *   Save the new community to the database.
4.  An "Edit Community" page (`/admin/communities/[id]/edit`) must allow the administrator to:
    *   Load an existing community's data into the form.
    *   Modify any of the community's fields.
    *   Save the updated community to the database.
5.  All CRUD operations must be performed via secure API endpoints, accessible only to authenticated administrators.
6.  Client-side and server-side validation must be implemented for all form fields.
7.  The admin interface must be responsive.
